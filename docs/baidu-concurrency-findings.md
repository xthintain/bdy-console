# 百度网盘开放平台并发能力实测与工程约束

状态：已验证（2026-09-02 实盘压测）

本文记录百度网盘开放平台（Baidu Pan Open Platform）对**并发访问**的支持程度、官方文档给出的限制、本地真实压测数据，以及由此固化到 `bdy` / `bdynd` 的工程参数。目的：并发优化有据可依，不靠猜测。

## 1. 官方文档结论

来源：`pan.baidu.com/union/doc`（上传能力说明 / 分片上传 / 预上传 / 创建文件 / 下载 / 公共错误码 / FAQ / Android SDK）。

- **并发本身受支持**：官方唯一给出一致数字的是 Android SDK 配置 `uploadConcurrency`：**默认 2，最大可设 5**。可视为安全并发上限的保守参考。
- **上传三阶段串行**：`precreate → superfile2 → create` 必须按序执行（后一阶段依赖前一阶段返回值）；但**同一任务的不同分片之间允许并发上传**，官方 SDK 即按此模型实现。
- **没有统一的 QPS 门槛**：官方明确「开放平台仅对异常行为进行相应限制，不会影响到正常使用」「接口调用有频控限制，但出于安全策略暂不支持公开」。
- **分片大小**：普通用户单分片固定 4MB、单文件上限 4GB；分片数上限 1024；分片顺序号从 0 开始。
- **下载**：文件数量不设限；速度按账号身份（普通/会员/超级会员）限流；不支持 Range（整文件拉取）。

### 1.1 已知频控与硬性红线（命中即报错）

| 触发条件 | 错误码 | 说明 |
| --- | --- | --- |
| 单日上传调用超 10 万次 | `errno 9013` | 命中频率控制，需隔天再传 |
| `listall` 请求过快 | `errno 31034` | 官方建议不超过 8–10 次/分钟 |
| 测试应用（未上线审核）调用超限 | `errno 20012` | 访问超限触发限流 |
| 并发过高 / 带宽打满 | 连接断开 / 500 | 官方建议降低并发量，失败分片重传即可 |

> 注：`31034` 在官方 FAQ 中挂在 `listall` 接口上；`list` 接口无此说明，实测未见触发。

## 3. 结论与参数建议

- **并发收益真实存在**：单文件分片并发最优约在 8；多文件 / 下载最优在 4–8；收益约 1.5–2×；超过后因带宽与连接竞争反而下降。
- **本次压测未触发任何频控**：`9013 / 31034 / 20012` 均未出现，正常使用余量很大。
- 参数固化为：

| 参数 | 建议值 | 依据 |
| --- | --- | --- |
| 单文件分片上传并发 `BDY_UPLOAD_CONCURRENCY` | 默认 8，上限 16 | 实测最优；现有实现已如此 |
| 多块上传并发（`bdynd` TimelineSink） | 默认 4，上限 8 | 场景 B 实测最优 |
| 并发下载（`bdynd` 恢复） | 默认 4，上限 8 | 场景 C 实测最优 |
| 目录列表重试退避 | `31034 / 9013 / 20012` 指数退避 | 官方红线；正常使用不应触发 |
| 失败处理 | 分片/块级重传，残缺即重拉 | 官方建议 + 项目强校验原则 |

## 4. 已知平台坑：list 对深层目录返回空

实测发现：百度网盘 `list`（目录列表）接口对**目录层级较深**的路径（实测约 9 层以上，位于 `/apps/.../objects/<kind>/sha256/<prefix>` 这类对象仓库深处）会返回**空结果**，但文件实际存在：`search`、`filemetas`、`download` 均能正常命中。原因疑似 PCS list 的深度/缓存限制，官方文档未说明。

对本项目的影响与对策：

- `bdy nd` 的对象仓库远端布局恰好是 3 层深（`objects/<kind>/sha256/<prefix>/<hash>`），叠加 `/apps/.../nd/repos/<repo>` 前缀后很容易踩中。
- `ndRemoteStore.DownloadFile / Exists` 已改为：`List` 返回空时用 `Search` 兜底定位（`internal/cli/nd_remote_help.go`）。
- 未来 `RemoteTransfer.ListFiles`（listall 递归枚举）若依赖 List 遍历目录树，需改为基于 `search`/`listall` 的路径发现，避免漏掉深层对象。

## 5. 相关实现

- `internal/baidu/upload.go`：分片并发上传（worker pool + 失败即取消）。
- `internal/bdynd/timeline/transfer.go`：`BoundedTransfer`（并发上限 + 频控退避 + 失败块重试）。
- `internal/bdynd/concurrent.go`：`ConcurrentRunner`（push/fetch 可达对象并发传输）。
- `cmd/conctest`：并发/频控实盘测试工具。

## 6. 复跑方法

```bash
export PATH=$PATH:/usr/local/go/bin
go run ./cmd/conctest all       # 全部场景（上传/下载/列目录）
go run ./cmd/conctest upload-single
go run ./cmd/conctest upload-multi
go run ./cmd/conctest download
go run ./cmd/conctest list
```

注意：`cmd/conctest` 会向 `/apps/baiduyunStorage/concurrency-test` 上传真实文件并自动清理；需要已登录 token。
